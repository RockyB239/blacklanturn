# Per-section row customization and series status

Approved scope: local saved arrangements, separately for Home, Movies, Shows, YouTube (separate tabs), My Stuff and Add-ons; move, pin, hide, show and restore default arrangement. Preserve custom sources and all accounts/settings. Mac first with matched native timing, then Apple TV. Fire Stick and public builds remain unchanged. Previous preview/Options fix remains installed.

Approach: build on existing native BlackLanturn settings/dialogs with a small local overlay keyed by stable row identity. Keep provider definitions intact. Alternatives rejected: rewriting rows.json loses evolving YouTube categories; provider-side personalization adds calls. Read layout once per window; write atomically only on explicit choices. New provider rows append by default. A user cannot hide the last available row. If a changing upstream catalog temporarily removes every unhidden row, show one available fallback without erasing hidden preferences; normal filtering returns when the preferred category returns. Restoration clears arrangement only, keeping existing source definitions. Existing advanced row/source editor remains available separately. Episode/search/details pages are not rearranged.

Series labels: Returning series, Ended, Canceled, In production and Planned when known. Use TMDbHelper local public tvshow metadata in bounded, read-only batches on existing provider work, plus direct provider values. Never infer cancellation from dates or episodes and never block UI with new network lookups. Display in existing technical metadata line, keep watched state separate, blank for unknown and movie/episode/person items.

YouTube adaptive catalog refresh must preserve active shelves/focus and hide preferences, including when primary rows are reordered/hidden. Changes take effect on deliberate section entry; late shelves are appended without moving active cards. Saved layouts survive restart and in-place updates; no cross-device sync. Mac settings intentionally remain local, Apple begins with its own arrangement.

No browsing performance regression is acceptable without investigation: compare matched native cached section and deep-row navigation before/after. Verify selected card, row identities, pagination, restart persistence, reset and untouched authorizations. No new provider requests per title, timers or polling. No release/version/public package changes.
