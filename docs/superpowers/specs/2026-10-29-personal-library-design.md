# Personal library and next-series discovery
Approved conversational scope: personal collections, movie-series release order, multiple saved searches, and suggestions after natural completion of the last currently available episode, including returning series. Mac trial first; other devices and public distribution remain unchanged.

Collections live under My Stuff and accept movies and shows in multiple named shelves. Options can add/remove membership; management supports rename, ordering, title removal and collection deletion without changing watched history. Local metadata snapshots preserve wide artwork; watched status is refreshed by the existing watch pipeline. Persist in the existing preserved rows.json object, bounded and atomically written. No new account/service/background sync.

Saved searches retain name, exact query and supported search category, reopening current provider results with existing caching. Manage rename/delete separately from last-query clearing. Accessible from Search and My Stuff. No invented unsupported advanced filters.

Movie-series action opens the provider's franchise collection; order released movies by valid release date/year, retain native play/resume/status and highlight next released unwatched title. Future/missing-date titles remain visible but cannot be the next recommendation. Release order only; do not infer chronology. No additional provider request while scrolling; lookup only on explicit action.

Next-series suggestions use the existing branded end-screen style, three landscape choices, Details/Save/return and disable controls, no autoplay of a different series. Only natural full-video EOF qualifies, never Stop/error/preview/movie. Match actual final episode identity across chained episodes. Confirm latest aired episode using a fresh public TMDb details response; unknown/error/stale metadata means no suggestion. Existing next-episode handoff wins. Fetch recommendations asynchronously late in playback with bounded work and cancellation/ownership guards; never wait for them on return. Respect hidden/reduced titles and exclude the completed show. Details/open shows use ordinary BlackLanturn browsing.

Approaches: local existing preferences versus new Trakt collection API; choose local to avoid account scope/service complexity. Existing provider collection routes versus custom franchise catalogue; choose provider release order. Fresh public metadata through Helper’s exposed API versus a Kodi provider invocation or scanning all seasons; choose one asynchronous direct request with appended recommendations/similar, a 4-second socket timeout and 1MiB response cap, so recommendation activity cannot hold Kodi’s playback-return gate. Local shelves use read-only batched Helper sync-cache status. Reuse branded end-screen layout with isolated series-specific controls versus changing YouTube behavior; choose separate series dialog.

Constraints: Kodi21.3; existing OpenWizard updater; all settings/authorizations retained; personal Fight Zone unchanged; no added dependencies, network polling, idle metadata fanout or public release/version changes. Local edits must not overwrite malformed saved data. Test native behavior and automated contracts separately; record timing limits honestly.
